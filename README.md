# Heptabase → Obsidian 搬家指南

**讓 AI 幫你把 Heptabase 完整搬進 Obsidian。不用寫程式，也不用打開終端機。**

A migration guide for moving from Heptabase to Obsidian with an AI agent (Claude Code or Codex) — whiteboards, relations, images and journals included. Written in Traditional Chinese.

---

## 這是什麼

這不是一鍵轉檔工具。它是一份**搬家規格**：你把它交給 AI，AI 照著做；你在幾個關鍵點親眼檢查。

Heptabase 匯出的 Markdown 可以直接放進 Obsidian，但白板的位置、卡片之間的連線、白板裡的白板、沒有標題的圖片卡，都不會跟著過去。這份規格處理的，就是這些「檔案到了、內容沒到」的部分。

它來自我自己的搬家經驗：五週、三輪，3,312 張卡片、94 張白板、700 篇 Journal。前兩次都搬壞了，第三次才搬完整。

## 你是哪一種？

| 你的情況 | 從哪裡開始 |
| --- | --- |
| 還在用 Heptabase，第一次搬 | 看下面的「開始搬家」 |
| 已經搬過，也在用 Obsidian 了，但白板亂掉、圖片不見、連結斷掉 | 一樣看「開始搬家」，**第四步要多貼一段話** |
| 只有幾十張卡片，沒什麼白板 | 你不需要這份。直接用 Heptabase 匯出的 Markdown 就好 |

## 你需要準備

- **Heptabase 完整匯出**：設定 → Backup → Export now，**一定要勾「Include files and images」**。
- **一個空的 Obsidian Vault**：專門拿來試搬。不要在你正在用的 Vault 上直接做。
- **Claude Code 或 Codex**（桌面版就可以）。兩個都需要付費方案，每月 20 美元的方案做得到，只是額度用完要等。
- **一份原始匯出的備份**：放在別處，整個過程都不要動它。

## 開始搬家

**第一步：匯出 Heptabase。** 匯出很快。我的資料匯出後大約 5 GB、九千多個檔案。裡面那個 `All-Data.json` 一定要留著，白板的位置和關係都只記在這裡。

**第二步：把東西放在同一個資料夾。**

```text
我的搬家資料夾/
  Heptabase-Data-Backup-…/   ← 你的 Heptabase 匯出
  Obsidian_Test_Vault/        ← 空的測試 Vault
```

**第三步：在 Claude Code 或 Codex 打開這個資料夾。** 不用下載這份規格，把網址貼給 AI 就可以。

**第四步：貼上第一段指令。** 第一輪只讓 AI 看，不讓它改任何東西：

```text
請先讀這份搬家規格：
https://github.com/cindyinee/heptabase-obsidian-migration-guide/blob/main/guide.md

先不要修改任何檔案。

請檢查我的 Heptabase 匯出和 Obsidian 測試 Vault，然後告訴我：

1. 我有哪些資料、各有多少
2. 你建議哪些要搬、哪些只封存、哪些跳過，以及原因
3. 需要我做決定的項目
4. 主要的風險
5. 你建議先用哪一張白板試做

原始的 Heptabase 匯出只能讀，不能改。
在我同意試做結果之前，不要開始全部轉換。
```

**如果你已經搬過、也在用 Obsidian 了**，在指令最後再加這段：

```text
我已經在用這個 Obsidian Vault，裡面有我後來新增和修改的筆記。
不能整包覆蓋。請先列出哪些是舊的搬家結果、哪些是我自己新增或修改的，
只把缺的部分補回去。我自己寫的東西不要動。
```

## 接下來，你只要做兩件事

**1. 做決定。** AI 會問你很多問題：Journal 要不要搬？Highlight 要不要搬？沒有標題的卡片怎麼處理？回答之前，先反問它：

> 「這個答案會影響哪個決定？如果我選 A 或 B，最後在 Obsidian 裡看起來會差在哪？」

說得清楚影響的，才值得花時間想。

**2. 親眼檢查。** 先讓 AI 試搬一張最複雜的白板（有圖片、有連線、有心智圖、裡面還放了另一張白板），用 Obsidian 打開看。沒問題了，才全部搬。

全部搬完後，自己再做這五個檢查：

- [ ] 搜尋「empty card」和「media missing」，每一個都問 AI 原本是什麼
- [ ] 打開一張有子白板的白板，子白板還在裡面
- [ ] 隨便點 10 個筆記裡的連結，都打得開
- [ ] 打開幾張有圖片的卡片，圖片真的有顯示
- [ ] 筆記正文乾淨，沒有 `^` 開頭的亂碼、標題後面沒有多一串 ID

AI 說「0 個錯誤」不代表搬好了。沒被搬過去的東西，本來就不會出現在錯誤清單裡。

## 常見問題

**我不會寫程式，真的做得到嗎？**
做得到。你不需要看懂 AI 寫的程式，但要在試搬和搬完後，自己打開 Obsidian 看。

**Claude Code 和 Codex 用哪個？**
兩個都可以。我的經驗是：Claude Code 比較會抓大方向，收尾快；Codex 比較嚴謹，資料格式會比對到很細，但容易停不下來。我最後讓 Codex 定義格式、檢查細節，再讓 Claude Code 收斂和修問題。

**要花多久？**
我前後三輪、大約五週，大部分時間花在踩坑。有這份規格應該可以快很多。`[待補：上架後用公開版從頭再搬一次的實際時間]`

**我的筆記會被傳到哪裡？**
AI 工具會讀取你電腦上的筆記內容來工作。如果裡面有敏感資料，開始前先確認你的 AI 方案怎麼處理資料。

**搬壞了怎麼辦？**
整個過程都在測試 Vault 裡做，原始匯出只讀不改，所以隨時可以重來。

## 限制

- 這份規格來自一個人的資料。你的 Heptabase 版本、匯出格式可能不一樣，AI 要先檢查，不能照抄。
- Heptabase 匯出本身沒有的東西（例如部分圖片檔、側邊欄的排列順序），AI 也救不回來，但它應該列出來告訴你。
- 這是一份持續更新的規格。遇到新的狀況，歡迎開 Issue 告訴我。
